pygixml — benchmark suite, run module by module

How each part of the library compares

Instead of one throughput number, this walks the library one capability at a time — parsing, streaming, turning XML into objects/dicts/JSON, and the command line — each measured against the closest competitor that does the same job the same way.

Where two approaches build the same kind of structure (both hold a full result in memory, say), the report averages the per-file speed/memory ratio into a single E[target/ref] figure. Where one approach has a fundamentally different memory shape than the rest — bounded instead of growing with input — that's called out on its own rather than forced into a ratio.
